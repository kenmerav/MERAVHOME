# Shared construction-document extraction

Catalog fit and bathroom-layout suggestions share a single saved extraction of the latest construction PDF for all current project rooms. Opening another room, another item, or another server instance reads the saved result instead of resubmitting the PDF. The first extraction keeps the full PDF so plans, elevations and fixture schedules remain available together.

The cache lives in the existing private `spec_completion_reviews.report.catalog_fit_checks` JSON. No schema or environment change is required. The key includes project ID, document ID/revision/path/size/title, the sorted room IDs and names, target labels and extraction version. Changes to selected products do not invalidate extracted document facts; those selections are still checked live against the correct room's cached requirements.

An optimistic database claim is saved before the paid request. Concurrent openings join that job. Polling only retrieves its existing background response. Failures, expired jobs and incomplete room mappings stay unavailable, with no automatic paid retries. The existing catalog Retry action can explicitly restart an unavailable shared job. Successful legacy room results remain usable without paying to migrate them.

Every supplied room must be returned exactly once. Requirements retain the existing exact-object, explicit-specification, high-confidence, original-page, unit and conflicting-callout validation. Bathroom absence still requires a complete proposed layout with a supported original-page citation. Public room responses expose only that room's requirements, after the existing staff/project/room authorization. Original PDFs and project selections remain unchanged.

The extraction uses the existing pinned Sol model, default service tier and token-counting cost ceiling. One shared extraction reserves the completion output budget because it covers all rooms; this is a per-request estimate, not an account-wide spending cap. Incomplete output is rejected rather than silently dropping rooms. Projects over 100 rooms fail closed.

Full Spec Book completion reviews also save reusable evidence in the private `report.spec_drawing_evidence` JSON. The first successful full review reads the PDF and returns both current findings and selection-independent drawing facts. Its instructions require all rooms and pages, including the casita, presence of drawn items, exact variant counts, explicit scheduled areas, dimensions/specifications, and uncertainties. Subsequent changed-selection reviews send the current selection/shared-default/exclusion ledger and these facts as text; they do not download or attach the full PDF. An unchanged drawing and selection signature reuses completed findings without generating AI. Catalog fit and full-review extraction have different coverage and versioned keys; their first scans remain separate.

The full-review source key includes project, document ID/revision/path/size/title, sorted room IDs/names, and extraction version. Product, quantity, price and board edits require a fresh comparison but do not invalidate the drawing facts. New drawing versions or changed room mappings require a new extraction. Completed sources survive new server instances and new saved reviews. Two completed source versions are retained along with pending sources. Saving a review uses conditional row writes that preserve concurrent catalog/evidence caches and issue decisions; concurrent project reviews claim the row before paid work. No database schema, permissions, original documents, or environment variables are changed.

Every page and room must be accounted for; partial extraction, invalid citations, incomplete counts and unsupported facts fail closed. Comparisons must reference saved fact IDs. The server binds cited pages/sheets, quantity totals and shared allocations, values and dimension scope to those facts before applying existing finding validation. Shared allocations must include every saved count for the same exact variant. Unmatched rooms and drawing uncertainties are disclosed in the review message; absence of a fact is never proof an item is missing. Extracted facts remain AI-derived and need designer review; structural validation does not prove every visual detail was captured. Failed checks do not automatically restart generation. Legacy pending responses still collect through the existing workflow. Targeted dimension buttons and other AI operations remain separate.

Full review verification covers unchanged-review reuse, changed/new selection comparison without PDF inputs, cold-server reuse, document/path/room invalidation, simultaneous review claims, background extraction and comparison collection, source retention, private cache omission, incomplete extraction, original citations, exact dimensions, and shared allocations. Tests mock AI and incur no API charges. Both extraction and comparison retain the existing pinned model, default tier, output/token cost guard, and thirty-minute background collection window. Actual savings depend on the PDF and the number/size of extracted facts; a text comparison can still incur AI cost.

Layout route tests retain active staff and assigned-project access checks. Model cost guard tests remain unchanged.
